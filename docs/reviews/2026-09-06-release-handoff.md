## 반드시 유지할 데이터 계약

- **원천을 더하지 않는다.** MES 형합×Cavity 추정, 현장 불량 체크포인트, 수기 `InjectionReport`, 관리자 `ProductionExecution`, 품질 `QualityReport`는 서로 다른 레코드다. 같은 품번·설비라는 이유만으로 합산·중복 제거·자동 덮어쓰기를 하지 않는다.
- **시간 기준을 분리한다.** 생산/MES는 Shanghai 08:00~다음날 08:00 업무일, 품질 분석은 `report_dt`의 Shanghai 00:00~다음날 00:00 달력일이다. 업로드 시각이나 현재 계획일로 과거 발생일을 바꾸지 않는다.
- **0·미기재·실패를 구분한다.** 명시된 0은 유지한다. 기재 수량이 하나도 없으면 `null`, 조회 실패는 오류 상태다. 갱신 실패 중 캐시를 최신 확정값으로 평가하거나 CSV로 내보내지 않는다.
- **품질 수량의 범위를 함께 보여준다.** 불량 수량 합계는 유효하게 기입된 신고 행의 합이다. 신고 원장은 전체 생산/검사 모집단이 아니므로 전체 불량률·양품률·OEE를 계산하지 않는다. 검사 수량도 같은 LOT이 반복될 수 있다.
- **분모와 표본을 명시한다.** 품질 Pareto는 신고당 하나의 버킷이며 복합 유형을 중복 배정하지 않는다. 집중도 비중은 선택 범위 전체 신고를 분모로 하고 상위 20그룹 밖 건수를 별도로 둔다. 그룹별 원본 ID 최대 5개는 전체 원장 목록이 아닌 표본이다.
- **설비 귀속을 추정으로 메우지 않는다.** 품질의 설비는 원본 발생 위치에 명시된 번호만 연결하고 나머지는 미지정으로 둔다. 현재 생산계획을 과거 사건에 소급 적용하지 않는다.
- **계수와 저장 집계의 한계를 보존한다.** 첫 관측에 기준 계수가 없으면 누적 전체를 구간 실적으로 가산하지 않는다. 저장 버킷은 조회창에 완전히 포함되고 원시 capacity 관측이 없는 경우에만 보충한다. 원시 slot 귀속과 저장 writer의 샘플 사이 시간 비례 배분은 다르며, 후자는 측정 가동시간이 아니다. 기존 저장 버킷의 계산 버전은 미확정이다.

## UI 확인의 실제 제한

품질 분석의 독립 CUA 검증은 IAB 탭 연결 한 번에서 `Browser is not available: iab` 오류로 중단됐다. 이전 주 작업에서도 브라우저 연결 제한이 보고되었으므로, 이후 사용자의 Chrome 세션이나 다른 제어 방식으로 우회하지 않았다. 이 시도에서는 프록시 변경·재시작, 화면 이동, 원본 보고서 요청을 수행하지 않았다.

따라서 품질 분석의 데스크톱/작은 화면 레이아웃, 중국어 문구 배치, 원본 모달, 필터 조작, 실제 CSV 다운로드는 브라우저에서 완료 검증했다고 주장하지 않는다. 타입·정적 검사와 합성 수치 검증은 이를 대체하지 않는다.

작동하는 검토 브라우저에서 다음을 확인하고 최상단 배포 후 확인란에 결과를 기록한다.

1. 같은 날짜·설비로 사출 개요→현장 기록→모니터링을 왕복하고, 과거 조회에서 현재 현장 입력으로 넘어가는 안내를 확인한다.
2. 수기 `#new` 링크가 입력을 열고, 미저장 실행 행을 둔 채 날짜·설비를 바꿔도 기존 작성 내용이 보이는지 확인한다. 저장 검증이 필요하면 격리된 쓰기 fixture에서만 수행한다.
3. 품질 분석에서 기간·공정·미지정 설비를 적용하고 요약·추세·표·CSV의 적용 범위를 대조한다. 수량 공백과 명시된 0을 따로 확인한다.
4. 원본 모달의 ID와 선택 그룹을 확인하고 뒤로가기/필터 변경 시 이전 범위 모달이 닫히는지 확인한다. 합성 ID의 상세 GET은 합성 응답으로만 처리하며 운영 원장으로 전달하지 않는다.
5. 새 조회/갱신 오류, 빈 응답, 일부 수량 미기재를 각각 확인한다. 실패 시 정상 0·최신 판단·CSV가 나오는지 확인한다.
6. 한국어/중국어와 좁은 화면에서 차트 축·단위·표 가로 스크롤·버튼·모달 닫기를 확인한다.

## Mac Studio에서 안전하게 이어받기

기존 Mac Studio 작업을 먼저 확인한다. 아래 절차는 로컬 변경을 지우는 초기화 절차가 아니다.

```bash
git status --short --branch
git branch --show-current
git fetch origin
```

작업 중인 변경이나 커밋이 있으면 먼저 해당 작업의 소유와 보존 위치를 확인한다. 미커밋 변경은 현재 작업 브랜치/별도 worktree에서 보존하고, 검토 없이 자동 stash·덮어쓰기·삭제를 하지 않는다. 충돌 가능성이 있으면 이 상태에서 인수를 멈추고 차이를 비교한다.

**위 PR이 실제로 main에 병합되었고 현재 작업 트리가 깨끗한 경우에만** 다음을 실행한다.

```bash
git switch main
git merge --ff-only origin/main
git status --short --branch
git log -1 --oneline
```

`--ff-only`가 실패하면 로컬 main의 커밋과 원격 main이 갈라진 것이다. 로컬 변경과 커밋을 보존한 채 브랜치 차이를 검토한다. `git reset --hard`, 강제 push, `git clean`으로 맞추지 않는다. PR이 아직 main에 반영되지 않았다면 main을 완료 상태로 간주하지 말고 위 개발 브랜치의 변경만 별도로 검토한다.

업데이트 뒤 표시된 SHA를 PR #34의 main 병합 SHA 및 실제 서비스 버전과 비교하고 의존성·검증을 수행한다. 후속 개발은 갱신된 main에서 별도 작업 브랜치로 시작한다. 브라우저/API 배포 반영 여부는 로컬 Git SHA와 별도로 확인한다.
