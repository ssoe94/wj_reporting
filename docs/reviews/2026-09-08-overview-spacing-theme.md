# 종합현황판 여백과 주야간 화면

대상은 `/boards/overview`이며 2026-09-08 사용자 피드백을 반영한다.

## 구현된 동작

- 중앙 카드 하단의 그래픽 조작·데이터 최신성 행을 제거했다. 시계·기상 영역이 남은 높이를 사용하고, 글로브 하단의 한 줄 반투명 캡션을 유지한다. 갱신 실패는 기존 새로고침 버튼의 색·설명과 접근성 상태로 알린다. 수신 시각과 DEMO 구분도 유지한다.
- 사출·조립의 계획/실적 묶음을 그림과 오른쪽 진도 영역 사이의 가운데에 배치했다. 숫자 묶음 안의 라벨·수량은 왼쪽 정렬하며, 자릿수에 따라 기존 글자 크기 조절을 유지한다.
- 로고는 제목 행 안에서 크기와 왼쪽 여백을 줄여 정렬했다. 추가 아이콘 없이 로고만 누르면 라이트/다크 모드가 전환된다. 가운데 제목의 중심은 변하지 않는다.
- 북경 시간(Asia/Shanghai) 08:00 이상 20:00 미만은 라이트, 그 외는 다크를 기본으로 한다. 수동 선택은 이 브라우저에 저장되며 다음 08:00/20:00 경계에서 자동 설정으로 돌아간다. 저장을 사용할 수 없는 브라우저에서도 현재 탭의 전환은 작동한다. 다른 탭의 변경, 잠든 탭의 복귀, 시계 변경을 재확인한다.
- 다크 모드는 종합현황판에만 적용한다. 남색 바탕과 밝은 숫자·보조 문구, 기존 의미의 파랑/초록/주황을 사용한다. 차트, 출고, AI, 날씨 캡션과 조회 실패 화면도 함께 전환된다. 밝은 화면의 기존 색은 CSS 기본값으로 유지한다.
- 중국어 카드 제목 8개와 중앙 운영센터 제목을 모두 900 굵기로 맞췄다. 로고의 전환 마크는 사용자 최종 지시에 따라 제거했다.

## 구현 위치

- `OverviewBoardPage.tsx/.module.css`: 상단 배치, 갱신 실패 안내, 다크 토큰, 차트 색, 중국어 제목.
- `overview/theme.ts`, `useBoardTheme.ts`: 시간대·경계 계산, 수동 선택과 만료, 탭 동기화.
- `overview/BoardThemeLogo.tsx/.module.css`: 이미지 전용 로고 버튼과 접근성.
- `overview/WeatherDisplay.module.css`, `QualityBriefingContent.module.css`, `OutboundPerformanceContent.module.css`: 다크 모드 색과 캡션.
- `overview/OverviewArtwork.module.css`: 삭제된 그래픽 조작에 종속된 수동 일시정지 선택자 정리. OS 움직임 감소는 유지.
- `frontend/tests/overview-theme.test.ts`: 시간 경계, 시간대, 연말·자정, 수동 선택 만료, 잘못된 저장값 검사.

생산 수량·계획 배분·MES/API 계약, AI 생성, 백엔드, 마이그레이션, 운영 설정과 이미지 자산은 변경하지 않았다. 화면 테마는 기상청의 주야간 관측 상태나 생산 기준일을 바꾸지 않는다.

## 검증

- 프런트 전체 단위 검사 161개 통과, 전체 ESLint 오류 0개·기존 경고 31개, TypeScript와 production/legacy build 통과.
- 독립 코드 검토 후 갱신 실패 안내 누락을 복구했고, 새 시간대·저장 동작 검토에서는 추가 결함이 발견되지 않았다.
- 합성 자료로 한국어·중국어, 8자리 수량, 음수 기온, 긴 날씨 상태·날씨 미수신, 다크 전체 9개 카드와 차트를 확인했다. 제목·생산 수량의 수평 넘침이 없고 중앙 제목 중심 차이는 0px였다.
- 로고 클릭과 Enter 전환, 다른 탭 동기화, 페이지 재로딩 후 수동 다크 유지, 전환 마크 부재를 브라우저에서 확인했다. 갱신 실패 시 수량과 수신 시각이 유지되고 버튼 설명이 실패 상태로 바뀐다. 최종 브라우저 오류 로그는 비어 있었다.
- 실제 08:00/20:00 현장 장시간 관찰은 하지 않았다. 해당 시각과 양쪽 1ms 경계는 단위 검사로 검증했다. 4K 실기·현장 시청 거리 검증은 남아 있다.

화면 비교와 검증 범위는 [design-qa.md](../../design-qa.md)에 기록했다. 운영 화면·수치는 저장소에 추가하지 않는다. 배포의 최종 상태는 이 브랜치 PR 본문, main의 Test and Deploy 실행 결과, 운영 build-info.json의 SHA로 확인한다.
