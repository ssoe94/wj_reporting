# 품질 신고의 모델·생산 연결과 생산시프트당 신고 빈도

- 생산이 확인된 시프트 수와 사출 품질 신고 건수가 각각 어떻게 변하는가? 분모가 확인된 날짜의 신고 빈도는 얼마인가?

앞선 [Pareto·시계열·형합 날짜 표시](2026-09-07-quality-pareto-trends.md)는 [PR #35](https://github.com/ssoe94/wj_reporting/pull/35), main `3fccf951e40db85ab37a322abc2a66423aab4dc7`로 배포됐다. 이번 개발은 그 위의 별도 증분이다.

## 모델과 생산 연결

품질 원장의 `model`을 주 정보로 사용하고, 수입 원장의 `item_name`이 있으면 함께 표시한다. `BC`, `CA`, `GP`는 각각 `B/C`, `C/A`, `G/P`라는 동일 구분 표기로 정리하며 원문에 이미 있는 구분을 반복하지 않는다. 모델이 없는 경우 `모델 미기재`로 표시한다. 현재 마스터값으로 과거 모델을 채우지 않는다.

모델·품목 집중도는 모델 표기와 **전체 정규화 품번** 조합을 그룹으로 사용한다. 같은 품번에 다른 모델명이 적힌 경우 자동으로 같은 모델로 합치지 않는다. 설비·모델 집중도는 여기에 연결 설비를 추가한 조합이다. 두 표는 같은 선택 범위의 전체 품질 신고를 각각 집계하므로 서로 더하지 않는다. 신고 수와 수량 기재 건수, 기록 불량 수량, 전체 선택 신고를 분모로 한 비중, 최대 5개 원본 표본을 제공한다. 상위 20그룹 밖 신고는 별도 수치로 남긴다.

추가 설비 연결은 사출 공정검사(`LQC_INJ`)만 대상으로 한다. 정확한 전체 품번, 해당 생산일, 품질 모델이 있다면 정규화 모델의 일치가 필요하다. 품번의 일부 접두어만 같다는 이유로 연결하지 않는다.

| 연결 근거 | 적용 조건과 해석 |
| --- | --- |
| 실적 기록 연결 | 양수 실적의 사출일보 또는 pending이 아닌 양수 관리자 실행 기록에서 같은 날짜·품번·모델의 설비 후보를 확인한다. 신고 발생 설비의 확정 증명은 아니다. |
| 저장 계획 연결 | 해당 일자에 현재 저장된 양수 계획의 유일 후보다. 계획 재업로드가 과거 행을 교체할 수 있으므로 사건 당시 계획 복원이나 실제 가동 확정으로 해석하지 않는다. |
| 원본 설비만 확인 | 품질 원문에는 설비가 있으나 생산 후보 연결까지 확인하지 못했다. |
| 연결 확인 필요 | 여러 설비 후보, 모델 충돌, 원문 설비와 후보 불일치 또는 후보 장치가 불명확하다. 원문 설비를 바꾸지 않는다. |
| 생산 미연결 | 원문 설비와 유일 생산 후보를 확인하지 못했다. 신고를 집계에서 빼지 않는다. |
| 사출 연결 대상 외 | 다른 검사 부문의 신고다. 동일 품번의 사출계획을 근거로 사출 설비 책임을 지정하지 않는다. |

실적 기록과 계획이 서로 다른 설비를 가리키면 확인 대상으로 남긴다. 같은 설비의 중복 실적·계획 행은 신고 수를 늘리지 않는다. 품질 조회의 기존 `기록된 설비` 필터는 여전히 원장 위치를 기준으로 한다. 추가 후보 연결이 조회 대상 신고를 늘리거나 전체 품질 합계를 바꾸지 않는다.

엑셀 수입 신고는 원문의 날짜에 임의로 Shanghai 08:00을 붙여 저장한다. 이런 신고의 생산 연결 기준은 원문 날짜다. 시간 근거가 있는 수기 신고는 08:00 이전이면 전일 생산 업무일을 사용한다. 어느 경우든 보고 시점을 실제 불량 생산 시점으로 확정하지 않는다.

## 생산시프트당 품질 신고

**빈도 = 사출 품질 신고 건수 ÷ 가동이 확인된 설비 시프트 수**다. 단위는 `건/시프트`이며 백분율이 아니다. 한 시프트에 여러 신고가 있으면 1보다 클 수 있다. 명시적 불량 0이나 미분류 신고도 원장에 저장된 신고이므로 포함한다. 불량 개체의 비율, 전체 검사 합격률, 생산수량 기준 PPM과는 다른 지표다.

분모의 고유 키는 `(설비, 생산 업무일, 주간 또는 야간)`이다. Shanghai 기준 주간 08:00–20:00, 야간 20:00–다음날 08:00이며 설비 1대의 한 시프트를 1회로 센다. 여러 모델을 생산하거나 여러 계획·실적 행이 있어도 한 시프트를 여러 번 세지 않는다. 활동은 해당 시프트에 형합 증가가 한 번 이상 관측됐다는 뜻이고, 12시간 풀가동 환산값이 아니다.

분자는 `QualityReport` 중 사출 공정검사 신고를 같은 08:00–다음날 08:00 생산 업무일로 묶는다. 다음날 새벽에 입력한 수기 신고는 이전 생산 업무일에 포함된다. 전체 검사 부문을 선택해도 이 지표에 조립·수입·출하·고객 품질 신고를 섞지 않는다. 엑셀의 임의 08:00을 실제 발생시각으로 해석하거나 신고 건수를 주간·야간으로 분해하지 않는다.

화면 상단 품질 원장과 기존 기간 추세는 달력일 00:00–24:00이다. 새 시프트 지표의 08시 경계 때문에 같은 화면 기간에서도 신고 합계가 다를 수 있으며 두 날짜 기준을 표시한다.

### 관측 상태와 비율 보류

- **가동 확인:** 같은 장치의 유효 형합수가 해당 12시간 시프트 내부에서 증가했다. 저장 시각과 원시 MES 시각의 오차를 고려해 경계에 걸친 증가만으로 확정하지 않는다.
- **형합 미증가:** 하루 접기와 같은 연속 관측 기준이다. 양쪽 경계 기준 관측, 최대 10분 간격, 같은 장치, 유효 비음수 일정 계수가 모두 필요하다.
- **판정 보류:** 수집 공백, 장치 혼합, 계수 감소/reset, 비정상 값, 경계 근거 부족 등으로 판정할 수 없다.
- **미완료:** 아직 종료되지 않은 시프트다.

날짜별 네 상태 합은 `선택 설비 수 × 2`다. **판정 보류나 미완료가 하나라도 있거나 가동 시프트가 0이면 비율은 null**이다. 알려진 신고 건수와 가동 확인 시프트 수는 그대로 표시한다. 기간 비율도 전 기간의 근거가 확인된 경우 `Σ신고 / Σ가동 시프트`로 계산하며 일별 비율을 평균하지 않는다. 신고 조회 실패는 null을 반환하고, 형합 조회 실패는 가동 확인 수를 0으로 꾸미지 않도록 원천별 상태를 제공한다.

시간별로 압축된 과거 로그도 같은 시프트 내부의 증가를 보이면 활동 근거가 될 수 있지만, 증가가 안 보인다는 이유만으로 미가동을 증명하지는 못한다. 기존 rollup 0이나 계획 행 수로 분모를 메우지 않는다.

## API·권한·실패 처리

기존 품질 응답에 `production_context`와 `production_shifts` 보조 계약을 추가한다. 기존 quality schema, legacy 집중도·Pareto·요약은 유지한다. 품질 조회 권한 검사가 먼저 적용되며 새 원천은 읽기만 한다.

- 품질 원장을 집계할 때 같은 필터를 통과한 작은 projection을 생산 연결에도 사용한다. 원장 표본 ID나 상위 그룹만으로 전체 집중도를 만들지 않는다.
- 생산 후보는 사출일보·관리자 실행·생산계획을 날짜 범위로 각각 조회하고 합산 50,000행 상한을 적용한다. 초과나 DB 오류면 후보 추정만 중단하고 품질 모델·품번·원문 설비를 보존한다.
- 시프트 지표는 원시 형합 최대 300,000행, 사출 품질 신고 최대 50,000행의 독립된 두 범위 조회다. 날짜·설비별 N+1 조회가 없다. 기존 달력일 접기와 새 시프트 지표는 현재 각각 범위 조회를 수행한다.
- 프런트는 보조 계약별로 상태·분모·합계·비율을 검증한다. 하나의 보조 자료가 잘못돼도 품질 본체나 다른 정상 보조 자료를 숨기지 않는다.
- CSV는 모델, 보조 품번, 연결 근거별 건수, 시프트 절대 분자·분모·판정 상태·비율·날짜 기준을 담는다. 달력일 원본 일별 행도 계속 보존한다.

## 다음 수집·개발 순서

1. 품질 신고에 실제 발생일시 또는 시각 미상 표시, 생산 LOT/작업 ID, 발생 설비, 모델·부품 구분을 구조화한다. 보고일시와 발생일시는 별도로 보존한다.
2. 생산 이력에 모델 교체 시작·종료와 계획 버전, 실행 작업 ID를 보존해 후보 연결을 확정 작업 연결로 발전시킨다. 변경 가능한 현재 계획을 사건 당시 확정 자료로 취급하지 않는다.
3. 원시 형합 압축 전에 설비·시프트별 관측 구간, 최대 공백, 장치 식별/변경, 증가·감소/reset, 원시 MES 시각, 집계 정책 버전을 남긴다. 그래야 장기간에도 분모를 검증할 수 있다.
4. 날짜별로 적용할 기대 설비 목록과 설비 도입·폐기·통신 중단 상태를 관리한다. 현재 고정 17대 범위에서 관측되지 않는 설비를 임의로 분모에서 빼지 않는다.
5. 검증된 공통 형합 원천 조회를 재사용해 달력일 접기와 생산시프트 계산의 조회 중복을 줄인다. 기존 결과 비교 회귀를 유지하며 전환한다.
