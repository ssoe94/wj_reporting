# 생산계획 → 원료 확정 → MES 工单

2026-10-10 사용자가 확정한 업무 흐름이다. 담당자 안내와 실제 로그인 사용자의 처리 이력을 구분한다.

| 단계 | 업무 담당 | 작업과 다음 단계 조건 |
| --- | --- | --- |
| 계획 업로드 | 营业 · 徐佳 | 영업 Excel의 품번, SPEC, MODEL, LOT, 호기, 수량, 기간을 확인하고 계획 저장 |
| 원료 확정 | 자재 · 韦凯 | 품번의 전체 MES 用料清单에서 사용할 원료와 배합을 확인. 철물·부자재 행은 유지. 실제 확인자, 시각, 근거 기록 |
| 작업지시 | 营业 · 徐佳 | 확정된 전체 투입 목록과 계획을 검토하고 MES 생성 준비 후 선택한 工单 생성. 불명 응답은 재전송하지 않고 재조회 |

여기서 작업지시는 현재 연결된 **工单 생성**이다. MES 下达·开工·재고 이동은 포함하지 않는다. 계획이 변경되면 현재 버전의 원료 확인이 필요하고, 이전 확인은 추천으로만 사용한다.

## 로컬 구현

기존 생산계획 화면에 담당 단계와 할 일별 필터를 추가했다. 원료 확정 대기, 영업의 생성 대기, 결과·변경 확인, MES 생성됨을 실제 상태에서 계산한다. 생성 ID만으로 완료를 추정하지 않으며, 생성 후 보고·입고 조회가 남은 상태도 별도로 표시한다. 편집 중 행은 서버 갱신으로 단계가 바뀌어도 화면에서 보존한다.

用料清单에는 저장된 모든 투입품을 표시한다. 원료 하나를 교체해도 다른 행과 비율을 유지한다. 실제 확인자·상하이 시간, SPEC·MODEL·LOT도 표시한다. 업로드 성공 후 확인 화면으로 이동할 수 있다. 부문 매핑은 사출 ZS, 가공 JG이며 MES 계획부서 002(营业), 계획원 2299(徐佳)를 전송하고 기본정보 재조회로 검사한다.

## 완료로 볼 수 없는 항목

- 현재 선택지는 저장된 MES 재고 목록이며 품번별 전체 BOM을 자동 조회한 결과가 아니다. 원료/철물 구분과 필수 BOM 행 보존을 서버에서 강제하는 연결이 필요하다. 현재 UI는 이를 구현했다고 표시하지 않는다.
- 담당 이름은 업무 안내다. approve/prepare/send가 공통 계획 편집 권한을 사용한다. 실제 WJ 계정과 역할을 대조해 원료 확정/생성 권한을 서버와 transport 양쪽에 적용해야 한다. 관리자 대행은 실제 관리자 이름으로 기록해야 한다.
- 원료 확정은 기존 승인 snapshot을 사용한다. 새 승인 테이블을 만들 필요는 없다. BOM 연결 시 원본 식별·버전/해시와 전체 확정 입력을 이 snapshot에 보관하고, 부자재 누락이나 변경된 BOM으로 생성하지 않도록 검사한다.
- Excel 기반 규격·분류는 기존 MES 값 유지, 공란만 보완한다. B/C·BASE만으로 완제품/반제품을 추정하지 않는다. 사용자 확정: ACQ30854202 → 반제품 后盖板 CAT-000, MAM66002511 → 반제품 base CAT-137. MES 물료 상세 API는 추가 권한이 필요하고 전체 편집 API의 생략 필드 보존은 아직 검증되지 않았다.
- MES 번호 규칙의 실제 설정과 한 번 발급한 번호의 보존 경로가 미완료다. 번호 발급은 조회가 아니라 번호를 소비하는 동작으로 취급한다.
- 직접 확정한 B8826을 보존하면서 BOM 버전을 표시하는 계약은 미확정이다. 버전 표시를 위해 useBomFlag를 임의로 바꾸지 않는다.

## 검증과 남은 인수

로컬 frontend 테스트 46건이 통과했다. 단계 분류, 편집 중 갱신, 실제 확인자/시각, 원료 교체 시 다른 자재 보존, 기존 전송 중복 방지와 계정 변경을 검증했다. 부문/계획원 전송 변경은 격리 backend suite 277건(6건 PostgreSQL 전용 skip)으로 검증했다. full application fixture 빌드와 legacy CSS 빌드가 통과했다. 브라우저에서 한국어·중국어 전환 중 초안 유지, 합성 원료 확정 저장→MES 생성 준비, CSS 1280px/390px 화면을 확인했다. 390px에서 발견한 가로 넘침은 패널 min-width 수정 후 재검증했다. 배포 및 두 담당자의 운영 로그인 검증을 대신하지 않는다.

별도로 승인받은 운영 MES 공란 보완은 UI에서 규격 9건, 분류 3건을 저장했다. 순수 APP 재조회로 이전/이후 31개 물료를 비교했으며 변경 경로는 specification 9건, category/categoryAllLevel 3건뿐이었다. 기존 비공란 규격은 유지했다. 이 일회성 보완은 Excel 업로드 후 자동 동기화 기능의 완료 증거가 아니다. 원본 체크와 결과는 주 체크아웃 `output/mes-metadata-20261010/master-blank-fill-verification.json`에 있다.

M1은 코드·빌드 통과로 완료되지 않는다. 미해결 계약을 확인한 뒤 시험 工单 한 건을 생성하여 부문, 계획부서/계획원, 전체 자재·원료, 수량, 규격·분류, 번호·버전을 MES 화면과 API로 확인해야 한다. 기존 실제 1,920개 건의 현장 수량·원료 확인은 M2의 부분 증거로 유지한다.
