# 근거 중심 분석과 현장 데이터 수집 개발 계획

검토일: 2026-09-06. 대상: `/analysis`, `/field/imm01`을 포함한 사출 현장 칸반.

## 목표와 근거의 범위

경영진에게는 생산계획 대비 차이와 확인할 문제를, 실무진에게는 해당 설비의 원인 기록과 다음 작업을 제공한다. 새 지표는 원천 데이터의 의미·기간·분모·누락을 검증한 뒤 추가한다. 화면이 비어 보인다는 이유만으로 미사용 페이지라고 판단하지 않는다.

이 문서는 공개 저장소에 전달하는 개발 명세다. 운영 원본 응답, 실제 생산·품질 수치, 사용자 정보는 포함하지 않는다. 코드 검토와 화면/API의 제한된 읽기 점검을 수행했으며, 전체 운영 DB의 30/90일 전수 프로파일을 완료했다는 뜻은 아니다. 수집 스케줄의 코드상 설정과 실제 실행 이력도 구분한다.

## 첫 개발 범위

1. `/analysis`의 첫 화면을 공통 업무일의 MES·생산계획 기반 분석으로 연결한다. 08:00~다음 날 08:00, Asia/Shanghai 기준을 표시한다. 공정별 계획과 실적, 부족분, 우선 확인 설비를 함께 보여준다.
2. 기존 현장 불량 체크포인트를 인증된 읽기 API로 집계한다. 현장 입력은 기존 저장 경로를 유지한다. 원인별 신고수량, 설비별 기록, 마지막 입력, 중복·이상값 제외 내역을 분석에 연결한다.
3. 모델체인지 확인에서 기존에 지원하는 실제 정지 사유와 조치·인계 메모를 입력하고, 당일 확인 기록을 다시 볼 수 있게 한다. 같은 사실을 다른 양식에 중복 입력하게 하지 않는다.
4. 데이터 요청 실패, 수집 지연, 미기록, 유효한 0건 보고를 구분한다. 이전 값이 남아 있으면 갱신 실패를 알리고 최신 정상값처럼 보이지 않게 한다.
5. 기존 OEE·비고 정규식 기반 정지 분석을 경영 첫 화면에서 제외한다. 일보·품질·생산 상세 업무는 기존 화면으로 연결한다.

이번 변경에는 새 DB 테이블이나 마이그레이션, 운영 수집기 설정 변경이 없다. 공개 현장 화면의 기존 권한을 확대하지 않는다. 현장 기록의 전체 집계는 인증된 분석 화면에서 제공한다.

| 현장 불량 기록 | 유효한 체크포인트에 입력한 불량 수량·원인과 기록된 생산 구간 | 이벤트 수, 설비·품번, 형합 구간, 기록시각, 제외·중복 내역 | 전체 공장 불량률, 검사 전수 커버리지, 불량 없는 설비 수 |
| 불량 0건 보고 | 유효한 기록이 있고 신고 불량이 0인 상태 | 기록 건수와 해당 생산 구간 | 기록 자체가 없는 설비의 품질 정상 판정 |
| 현장 차감 후 수량 | 기록 구간의 추정 생산수량에서 신고 불량을 차감 | 추정 분모와 신고 범위 | 검사 합격품·출하 확정 양품 |
| 과거 품질 주의 | 현재/계획 품번에 연결되는 과거 검사·문제 이력 | 조회 범위, 품번 매칭 기준, 마지막 보고 | 선택일 신규 불량수, 전체 불량률 |
| 출고 주문 이행 | 계획 시각으로 분류한 주문 라인의 현재 누적 이행량 | 계획/이행 기준, 조회시각, 주문종류·단위 | 실제 출하시각 기준 일출하량, OTIF |
| 재고·금형 등 스냅샷 | 해당 원천이 제공한 시점의 상태 | 원천시각, 수집시각, 지연·누락 | 과거 업무일을 선택했다고 당시 상태가 복원된다는 주장 |

원천의 행 수는 단위를 확인한 뒤 표시한다. MES 샘플 수, 검사보고 건수, 주문품목 수, 재고 SKU 수를 같은 의미로 취급하지 않는다. 원천의 최신시각만으로 관측 구간 전체의 완전성을 보장하지 않는다.

특히 기존 overview의 설비 행 상태·최신시각은 전체 사출 소스의 시각을 공유하는 경로가 있다. 따라서 일부 설비만 끊긴 상태를 해당 행의 `ok`만으로 배제할 수 없다. 설비 목록은 확인 후보로 사용하며 실제 정지나 원인을 확정하지 않는다. 다음 수집 개선에서 설비별 `latest_sample_at`, 기대/수신 샘플과 연속 누락 구간을 우선 제공한다.

## 전수 프로파일에서 채울 증거

승인된 내부 점검 환경에서 최근 30 업무일을 먼저 확인하고 보존 범위가 충분할 때 90일로 확장한다. 결과는 운영 수치를 포함하므로 공개 PR에 올리지 않는다.

1. 소스별 날짜·설비/공정별 행 수, 최초/최종 기록, 원천 최신시각과 마지막 성공 수집시각, 유효 관측/기대 관측, 최대 연속 누락.
2. 계획만 있음/MES만 있음/일치, 품번·설비 정규화 실패, Cavity 기본값·유효일 누락, 가공 미대사 잔량과 지연 수정.
3. 체크포인트 중복·잘못된 업무일/설비·수량 불일치, 원인합계 대사, 교대별 실제 기록 범위. 신고가 적다는 사실로 낮은 불량률을 결론내리지 않는다.
4. 품질 정상검사 포함 여부·검사 분모·결함품과 결함건 차이·중복 import·실행/LOT 연결률.
5. 재고 스냅샷 실제 보존일과 원천시각, 출고 주문 변경·분할 출하 이력, 금형 최신성.
6. analytics mart를 다시 활용하기 전 저장시각·원천 변경·양 공정 커버리지와 live 합계를 대사한다. 현재 `is_stale=False` 고정 경로는 별도 수정 대상으로 남는다.
7. 페이지 조회와 실제 작업 성공률은 별도 사용성 데이터로 측정한다. 업무 데이터 0건을 페이지 미사용 증거로 사용하지 않는다.

각 발견은 `검사 시점 / 대상 범위 / 분자·분모 / 근거 원천 / 영향 지표 / 담당 역할 / 조치 / 재검증 결과`로 남긴다. 충분한 증거가 없는 원인·추세·재무 효과는 가설로 표기한다.

## 다음 개발 완료 기준

- 첫 증분: 실제 원천에 연결된 분석 화면과 현장 기록 흐름, 유효한 0/미기록/오류 회귀 검증, 기존 권한·단위·업무일 유지.
- 다음 증분: 수집 실행 이력과 교대별 기대 기록 분모를 정의하고 누락 사유를 현장에서 보완. 이 단계가 완료된 뒤 기록완료율·정지 원인 추이를 신뢰 지표로 승격.
- 이후: 실제 실행 ID와 검사 분모 연결 → 납기 이벤트와 재고 보존 → 검증된 OEE·비용 우선순위 순으로 진행.

각 증분은 별도 PR과 검증 결과로 인계한다. 운영 반영은 기존 main 검증·Render 배포 절차를 사용하며 실제 배포 SHA와 health를 확인한다.
