# 인원 명부와 급여표 사번 검증

2026-11-12 WO-01. 인사 담당자가 급여표의 사번을 원본과 대조할 수 있도록, 요청에 따라 인원 명부와 배치 화면에 직원 이름을 표시한다. 두 화면은 기존 HR 권한으로 제한하고 명부 응답은 `private, no-store`를 적용한다.

- 직원 명부와 변경 이력은 새 테이블에 저장한다. 기존 월별 스냅샷과 분류표를 마이그레이션하지 않는다. 급여표에서 빠진 직원은 해당 월의 미포함으로 표시한다.
- 추천은 이름과 고용 형태의 정규화 일치를 전제로 한다. 계약직은 인접 월 고정급 차이, 시급직은 인접 월의 동일 부서를 확인한다. 사용자가 추천 적용을 누르면 해당 급여표 행만 수정된다.
- 같은 사람의 월별 사번이 다를 때는 확인 항목을 한 번 표시한다. 사번과 사유를 확인해 저장하면 이전 사번과 실행자가 기록된다. 보류한 경우 급여표의 사번과 월 합계를 그대로 저장하고 명부 연결을 보류한다.
- 기존 월 자료는 그대로 읽을 수 있다. 명부는 회사 급여표의 확정 저장에서 구축한다. 명부 편집은 버전 확인을 거치며 이전 급여표를 소급 수정하지 않는다.

WO-01 검수 수정 1회차:

- 수동 사번·상태 변경은 사유가 필수이며, 변경 전후 사번·상태와 서버가 기록한 실행자·시각을 같은 트랜잭션의 이력에 남긴다. 업로드 확정의 사번 결정도 같은 `HrRosterCodeHistory` 테이블을 사용한다.
- 명부는 기존 `identity()`와 `code_key()` 규칙으로 정규화 필드를 서버에서 계산한다. `(고용형태, 정규화 이름)`과 `정규화 사번`에 각각 DB 고유 제약을 적용하며 저장 충돌은 409로 응답한다. 원본 사번 문자열은 보존한다.
- 미적용 `0005_hr_roster`만 수정한다. 기존 마이그레이션·월별 스냅샷·분류표는 바꾸지 않으며 운영 적용은 이번 작업에 포함하지 않는다.
- 월 선택의 연도 범위는 2020년부터 올해 다음 해까지를 기본으로 하되 URL의 선택 연도가 범위 밖이면 그 연도까지 포함한다.

WO-01 검수 수정 2회차: 정규화한 사번과 이름이 같으면 고용형태가 달라도 같은 직원의 전환으로 연결한다. 실제 고용형태 변경을 사번 충돌로 막지 않도록 기존 이름+고용형태 기준에 이 예외를 둔다.
고용형태별 월 목록을 확인 항목으로 표시하며, 보류 시 월별 급여만 저장하고 기존 명부는 유지한다. 확인 시 최신 월의 고용형태·부서와 변경 전후 값·사유·서버 실행자를 같은 이력 테이블에 기록한다.
이름이 다르면 사번 충돌이며, 같은 이름이라도 고용형태와 사번이 모두 다르면 별개 직원으로 유지한다. 두 DB 고유 제약과 단일 미적용 마이그레이션 `0005`는 유지한다.

WO-01 검수 수정 3회차:

- 인원 명부를 `/hr/roster?month=YYYY-MM`의 본문으로 옮기고 인원 배치·인원 명부·인건비 집계 탭과 동일 월의 바로 가기를 제공한다. 재직·퇴사·해당 월 급여 미포함 요약에서 필터를 선택하며 사번·이름·이전 사번을 검색한다.
- 직원별 이력은 행을 펼칠 때 기존 명부 상세 경로의 GET으로 읽는다. 서버 기록 시각과 ID 역순으로 최대 20건을 반환하고 실행자·사유 및 변경 전후 값을 보여 준다. HR 권한과 `private, no-store`를 유지하며 이력 수정·삭제 API는 추가하지 않는다.
- 기존 명부 수정의 버전 확인·변경 사유와 급여 업로드 검증은 유지한다. 이번 변경에는 모델·마이그레이션 변경이나 운영 적용이 없다. 화면 검증에는 합성 자료만 사용한다.

## WO-02 1단계: 인건비 기준과 계산 엔진

- 사용자 결정: 평일 부서 기본 야근은 注塑·模具·公务·品质 4시간, 加工·营业·资材 2.5시간, 开发 1시간이다. 계약직 실적 야근수당은 `基本工资 ÷ 21.75 ÷ 8 × 시간 × 배수`이며 평일 1.5, 휴일 2, 법정 공휴일 3을 초기 기준으로 둔다. 제외 직무는 평일 수당만 제외하고 휴일·공휴일 수당은 유지한다.
- 위 산식은 감독자가 원본 대조로 제공한 근거를 구현한 것이며 이번 작업에서 실제 급여 파일을 읽거나 독립적으로 재검증하지 않았다. 계산 함수는 월 고정 `固定平时加班`을 실적 수당에 자동으로 더하지 않는다. 시급직은 초기 할증 꺼짐으로 계산하되 확정 전 결과 상태는 `unconfirmed`다.
- 미확정: 과장에 해당하는 실제 직무명, 부서 시간이 고정 연장수당을 포함하는지, 시급직 할증 여부. 미입력: 管理部·总经办 시간, 고용형태별 회사 부담 사회보험·공적금 요율과 기준액. 직원 급여 공제분을 회사 부담률로 사용하지 않는다. 제외 직무·고정시간 포함 여부가 미확정이면 일별 기본 시간은 `None`과 후보 시간·미확정 상태를 반환하며, 휴일 근무시간은 별도 입력이 필요하다.
- 적용 시작 월별 기준은 다음 시작 월 전까지 유효하다. 새로운 시작 월 조회는 이전 유효 기준을 복사한 버전 0 초안을 반환하며 GET은 저장하지 않는다. 달력은 월별 명시적 날짜 유형만 저장하고 미입력 날짜는 토·일 휴일, 나머지 근무일이다. 공식 공휴일·조정 근무일은 추측하지 않는다.
- `0006_hr_labor_standards`는 기준·달력과 각각의 이력 테이블만 추가한다. 두 저장 경로는 advisory lock을 스냅샷 전에 취득하고 버전·사유를 검사하며 변경 전후 값과 서버 실행자를 같은 트랜잭션에 기록한다. 기존 모델·마이그레이션·급여 자료는 수정하지 않는다.
- 순수 함수 `contract_overtime`, `hourly_pay`, `classify_day`, `month_day_counts`, `daily_default_overtime`, `employer_contribution`은 DB 없이 호출한다. `rules`, `version`, `effective_month`로 적용 기준을 전달하며 달력 함수에는 별도 `calendar_version`을 전달한다. 모든 결과의 `basis`에는 기준 버전, 단가, 시간, 배수가 있고 해당 없는 단가·시간은 `None`이다.
- Decimal 50자리 연산 문맥에서 중간 단가를 반올림하지 않고 최종 금액만 `ROUND_HALF_UP`으로 0.01 CNY 반올림한다. 항목별 금액과 합계는 각 원값에서 따로 반올림하므로 표시 항목의 합과 총액이 0.01 차이 날 수 있다. 입력은 문자열·정수·Decimal이며 float·음수·비유한 값은 거부한다.
- 이번 범위는 기준 관리와 계산 엔진까지다. 일별 입력(task 005), 예상 인건비 화면(task 006), 운영 마이그레이션·배포와 실제 원본 인수 검증은 포함하지 않는다.

## WO-02 2단계: 사용자 추가 결정 4–7과 통합 단가·요율

- 2026-11-12 추가 결정은 위 1단계 미확정 기본값을 대체한다. `Part長`, `部长`, `财务部长兼办公室主任`, `技术生产总经理`는 모든 부서에서 평일 **실적** 야근 제외로 확정하고 휴일·공휴일 수당은 유지한다. `工程师`는 기본 제외 대상이 아니며 HR에서 켤 수 있다. 부서 기본 시간은 실적 시간만 뜻하며 고정 연장수당 포함 여부는 아니오로 확정한다. 管理部·总经办의 제외 직무 미만 시간은 미입력이다.
- 시급직도 기본 근무 1배, 평일 야근 1.5배, 휴일 2배, 법정 공휴일 3배로 확정했다. 회사 기본 시급은 합성 초기값이며 확인 전에는 미확정이다. 직원별 시작 월·사유가 있는 예외가 회사 기본보다 우선하고, 해당 월 이전의 가장 최근 예외를 사용한다. 나머지 요율·기준액·적용 여부는 기준 시작 월의 버전과 함께 관리한다.
- 데이터 근거는 감독자가 제공한 WO-02 대조 결과와 사용자 결정이다. 실제 급여 엑셀을 이번 작업에서 읽거나 재검증하지 않았다. 기존 시급 급여에 할증 열이 없다는 사실은 향후 예상/실제 대조 설명에 사용한다. 급여표 보험·공적금 공제액은 직원 부담이므로 회사 부담률로 전용하지 않는다.
- 사회보험 5항목과 공적금은 회사·직원 요율, 공통/직원별/응발액 기준, 하한·상한, 고용형태별 적용 여부를 따로 저장한다. 생육의 명시적 0과 미입력 null을 구분한다. 항목의 어느 쪽 요율이든 미입력이면 해당 항목은 `missing`, 합계는 `partial_missing`와 null이다. 확인된 부분합은 별도 `known_totals`다. 보험·공적금은 **항목별 양측 금액을 HALF_UP 0.01로 반올림한 후 합산**한다. 기존 급여·실적 야근 함수의 중간 단가 미반올림 규칙은 유지한다.
- 월 회사 실제 납부액은 요율 추정과 별개로 `measurement: actual`로 저장한다. 총액/선택적인 고용형태별 금액/근거 메모를 기록하며, 완전한 분해는 총액과 일치해야 한다. 미입력은 0으로 간주하지 않는다. 변경은 사유·현재 버전·409·서버 실행자와 원자적 이력을 따른다. 조회는 기존 HR 권한, 수정은 `can_edit_hr_labor` 하나를 통해 현재 같은 HR 권한을 적용한다. GET은 저장하지 않고 모든 응답은 `private, no-store`다.
- 새 급여 가져오기는 정확한 `基本工资`·`固定平时加班` 열의 선택적 `payroll_components`를 보존한다. 최신 급여 월에서 현재/확인된 이전 사번 **및 이름**이 일치하는 행을 선택한다. 누락 항목을 더 오래된 값으로 채우거나 응발액에서 추론하지 않는다. 기존 저장 자료에는 자동 보완하지 않으므로 원본 항목이 없으면 누락 상태다. 출처 월·원본 좌표·월 자료 버전을 유지한다.
- `contribution_amounts(kind, employment_type, gross_amount=None, *, employee_id=None, rules=None, version=0, effective_month=None)`와 `resolve_hourly_rate(employee_id, month, *, rules=None, version=0, effective_month=None)`는 순수 계산이다. `employee_day(employee, day, *, payroll=None, regular_hours=None, overtime_hours=None, rules=None, overrides=None, version=0, effective_month=None, calendar_version=0)`는 급여/고정·실적·휴일·공휴일 야근/회사·직원 부담을 나눠 반환한다. 계약직 기본급·고정 야근·보험·공적금은 월 참조값, 시급 기본급과 실적 수당은 일별 금액이다. 월 참조값을 매일 합산하지 않는다. 계약직 기타 급여 항목·월 급여 배분과 비율은 아직 계산하지 않는다.
- 미병합·미배포 `0006`에 월 실제 납부액/이력 생성만 추가하고 마이그레이션 수는 유지한다. 운영 DB 적용은 없다. 이번 범위는 기준·요율과 계산 준비까지이며, 일별 입력은 task 006, 예상 인건비·비율·실제 대조 화면은 task 007이다.
- 로컬 합성 검증: HR 백엔드 162건 중 160 통과·SQLite 행 잠금 미지원으로 기존 동시성 2건 제외, 프런트 HR 112건 통과, 변경 TS lint 및 현대/레거시 빌드 통과. 합성 API 브라우저 10개 검사와 요청한 6개 캡처를 확인했다. PostgreSQL 실접속·실제 급여 재대조·운영 배포는 하지 않았다.
