# 인원 명부와 급여표 사번 검증

2026-11-12 WO-01. 인사 담당자가 급여표의 사번을 원본과 대조할 수 있도록, 요청에 따라 인원 명부와 배치 화면에 직원 이름을 표시한다. 두 화면은 기존 HR 권한으로 제한하고 명부 응답은 `private, no-store`를 적용한다.

- 직원 명부와 변경 이력은 새 테이블에 저장한다. 기존 월별 스냅샷과 분류표를 마이그레이션하지 않는다. 급여표에서 빠진 직원은 해당 월의 미포함으로 표시한다.
- 추천은 이름과 고용 형태의 정규화 일치를 전제로 한다. 계약직은 인접 월 고정급 차이, 시급직은 인접 월의 동일 부서를 확인한다. 사용자가 추천 적용을 누르면 해당 급여표 행만 수정된다.
- 같은 사람의 월별 사번이 다를 때는 확인 항목을 한 번 표시한다. 사번과 사유를 확인해 저장하면 이전 사번과 실행자가 기록된다. 보류한 경우 급여표의 사번과 월 합계를 그대로 저장하고 명부 연결을 보류한다.
- 기존 월 자료는 그대로 읽을 수 있다. 명부는 회사 급여표의 확정 저장에서 구축한다. 명부 편집은 버전 확인을 거치며 이전 급여표를 소급 수정하지 않는다.

WO-01 검수 수정 1회차:

- 수동 사번·상태 변경은 사유가 필수이며, 변경 전후 사번·상태와 서버가 기록한 실행자·시각을 같은 트랜잭션의 이력에 남긴다. 업로드 확정의 사번 결정도 같은 `HrRosterCodeHistory` 테이블을 사용한다.
- 명부는 기존 `identity()`와 `code_key()` 규칙으로 정규화 필드를 서버에서 계산한다. `(고용형태, 정규화 이름)`과 `정규화 사번`에 각각 DB 고유 제약을 적용하며 저장 충돌은 409로 응답한다. 원본 사번 문자열은 보존한다.
- 미적용 `0005_hr_roster`만 수정한다. 기존 마이그레이션·월별 스냅샷·분류표는 바꾸지 않으며 운영 적용은 이번 작업에 포함하지 않는다.
- 월 선택의 연도 범위는 2020년부터 올해 다음 해까지를 기본으로 하되 URL의 선택 연도가 범위 밖이면 그 연도까지 포함한다.

WO-01 검수 수정 2회차: 정규화한 사번과 이름이 같으면 고용형태가 달라도 같은 직원의 전환으로 연결한다. 실제 고용형태 변경을 사번 충돌로 막지 않도록 기존 이름+고용형태 기준에 이 예외를 둔다.
고용형태별 월 목록을 확인 항목으로 표시하며, 보류 시 월별 급여만 저장하고 기존 명부는 유지한다. 확인 시 최신 월의 고용형태·부서와 변경 전후 값·사유·서버 실행자를 같은 이력 테이블에 기록한다.
이름이 다르면 사번 충돌이며, 같은 이름이라도 고용형태와 사번이 모두 다르면 별개 직원으로 유지한다. 두 DB 고유 제약과 단일 미적용 마이그레이션 `0005`는 유지한다.

WO-01 검수 수정 3회차:

- 인원 명부를 `/hr/roster?month=YYYY-MM`의 본문으로 옮기고 인원 배치·인원 명부·인건비 집계 탭과 동일 월의 바로 가기를 제공한다. 재직·퇴사·해당 월 급여 미포함 요약에서 필터를 선택하며 사번·이름·이전 사번을 검색한다.
- 직원별 이력은 행을 펼칠 때 기존 명부 상세 경로의 GET으로 읽는다. 서버 기록 시각과 ID 역순으로 최대 20건을 반환하고 실행자·사유 및 변경 전후 값을 보여 준다. HR 권한과 `private, no-store`를 유지하며 이력 수정·삭제 API는 추가하지 않는다.
- 기존 명부 수정의 버전 확인·변경 사유와 급여 업로드 검증은 유지한다. 이번 변경에는 모델·마이그레이션 변경이나 운영 적용이 없다. 화면 검증에는 합성 자료만 사용한다.
