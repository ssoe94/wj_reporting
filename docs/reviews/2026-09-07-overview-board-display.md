# 종합현황판 표시 개선

대상: `/boards/overview`. 기존 3×3 구성, 공정별 파랑·초록과 경고 의미를 유지하면서 대형 화면에서 읽는 순서를 정리한다. 별도 작업 브랜치 `codex/overview-board-polish-20260907`의 구현 기록이며 배포 완료를 뜻하지 않는다.

## 실제 화면에서 확인한 문제

- 날씨 글로브가 시계·기상 정보와 보조 지표 뒤까지 겹쳐 표시됐다.
- 생산 수량은 자릿수가 늘어날 때 공간이 부족하고, 보조 지표는 상대적으로 작았다.
- 품질 카드의 긴 모델·상태 라벨과 여러 테두리가 핵심 문장과 확인 포인트의 공간을 줄였다.
- 에너지 차트의 음수 여백 때문에 Y축 숫자가 일부 잘렸다. 차트의 고정 픽셀 치수는 보드의 rem 기반 확대와 일치하지 않았다.
- 사출·조립 그림의 광택, 흰 외곽선과 세부 장식이 데이터 중심 현황판과 어울리지 않았다.

## 구현

- 중국어를 기본 검토 화면으로 삼는다. 중국어에는 PingFang SC/Microsoft YaHei 계열 글꼴과 자연스러운 자간을 사용하고 제목의 굵기와 줄 간격을 별도로 맞춘다. 언어 전환 시 데이터 정의와 3×3 구성은 동일하다.
- WJ 운영 센터 제목은 좌우에 같은 폭을 예약한 3열 헤더의 정중앙에 둔다. 로고와 조작 버튼은 좌우 독립 영역이며, DEMO 배지는 아래 출처 행에 둔다. 한국어·중국어 모두 제목과 카드의 가로 중심이 일치하는 것을 DOM에서 확인했다.
- `WeatherDisplay`를 표시 전용 컴포넌트로 분리했다. 관측 시각을 표시하며 미수신 또는 미확인 날씨에는 중립 아이콘을 사용한다. 미수신 때 남아 있는 온도·습도·풍속을 현재 관측처럼 보여주지 않는다.
- 최종 사용자 피드백에 따라 **시계–기상 정보–글로브** 순서로 배치했다. 기상 정보는 가운데, 새 글로브는 오른쪽이다. 이전 날씨 그림의 회색 배경과 multiply 합성을 제거하고 실제 투명 자산을 `object-fit: contain`으로 표시한다.
- 날짜와 위치에는 공통 라벨 행, 시각과 기온에는 공통 수치 행을 사용한다. 관측 시각은 ‘북경 현재 시각’과 같은 설명 행·글자 크기(0.7rem)로 맞췄다. 최종 사용자 피드백에 따라 날씨 상태는 **글로브 아래 중앙의 한 줄 반투명 캡션**으로 배치했다. 기온·글로브 두 열을 유지하고, 그림과 캡션은 같은 시각 영역에 묶었다. 한국어·중국어에서 날짜/위치, 시각/기온, 시각 설명/관측 시각의 top·bottom이 각각 일치한다. ‘구름 조금’·‘날씨 미수신’도 캡션 한 줄로 표시되며, −18.8°C와 겹치지 않는다.
- 시계·초·날짜·온도의 크기와 기준선을 정리했다. 생산 수량은 원래 값을 그대로 표시하면서 자릿수에 따라 글꼴 크기만 줄인다. 생산 보조 수치와 차트 눈금·범례를 키웠다.
- `QualityBriefingContent`는 장비·모델·품번, 핵심 요약, 이력 근거, 확인 포인트, 생성 출처 순으로 표시한다. AI 결과와 이력 참고를 구분하고 모델명 Qwen 3.8은 출처에 남겼다.
- 중국어 `12号机`가 말줄임되지 않도록 품질 카드의 설비명 열을 넓혔다. 최종 DOM에서 표시 폭과 내용 폭이 동일한 것을 확인했다.
- 문장이 긴 품질 페이지에는 12~45초의 읽기 시간을 배정한다. 수동 전환·일시정지, 포커스/마우스 진입 시 정지, reduced-motion 동작을 유지한다. 제한된 현황판 공간을 넘는 문장은 말줄임을 사용하며 전체 텍스트는 `title`과 DOM에 보존한다.
- `useBoardRem`으로 차트 축·범례·막대 치수를 보드의 확대 비율에 맞추고 음수 차트 여백을 제거했다.
- 조회 갱신 실패 시 기존 숫자를 유지하고 이전 수신 데이터라는 안내를 추가했다.
- 출고 실행은 `OutboundPerformanceContent`로 분리했다. JIT/CSKD별 실적·목표와 달성률, 동일 폭의 진행 막대, 미출고·잔량·초과, 우선 시간·품번 순으로 단순화했다. 지난주·지난달은 달성률 비교 두 줄로 표시하며, 누적 수량과 우선 품목의 세부 수량·원본 참조는 전체 설명에 보존한다. 내부 상자와 중복 라벨을 줄였다.

## 통일된 공정·날씨 그래픽

사용자는 ‘가공’이 이 화면의 조립 카드를 뜻한다고 확인했고, 비교 시안 중 **크리스털**을 선택했다. 날씨 글로브도 같은 계열의 정면 시점으로 맞춰 달라는 요청을 반영했다. 사출·조립은 모두 높은 장치가 오른쪽에 있고 바닥선은 수평이다. 글로브는 눈높이 정면 구도와 얇은 수평 크리스털 받침을 사용한다.

공통 프롬프트 방향은 정면 직교 구도, 파랑/초록 크리스털 테두리와 서리 낀 유리 몸체, 부드러운 조명, 작은 카드에서 식별되는 큰 실루엣이다. 위에서 내려다보는 받침의 넓은 윗면, 글자·인물·바닥·회색 배경·체크무늬를 제외했다. 선택 시안은 1536×1024의 두 공정 비교 이미지이며, 서비스 자산은 같은 방향과 재질을 따르는 개별 투명 이미지로 새로 제작했다. 시안의 배경과 제목을 카드에 복사한 것은 아니다.

모두 built-in `image_gen` 신규 생성본을 사용한다. 이미지 편집 변형에서는 체크무늬가 RGB 배경으로 생성되어 채택하지 않았다. 최종 PNG 원본은 `.codex/generated_images`에 유지하고, 서비스에는 크기·보이는 RGBA 픽셀을 그대로 보존한 무손실 WebP로 연결했다. 8개 전체의 알파와 보이는 픽셀이 인코딩 전후 동일한 것을 독립 검증했다.

모두 1254×1254이며 자산 합계는 약 9.34 MiB다. 처음 표시할 공정 2장과 해당 날씨 그림만 요청한다. 원본의 투명 여백 차이를 보정하기 위해 사출 이미지에 0.78rem 수직 오프셋을 적용해 보이는 바닥선을 조립과 맞췄다. 맑은 밤은 별도 이미지이며, 나머지 날씨의 야간은 같은 날씨 이미지에 어두운 색조를 적용한다. 구름 조금·안개·강한 비 등은 기존 그룹 매핑을 유지한다. 공정 그림은 식별을 위한 표현으로 실제 설비 모델 도면이 아니다.

사용자는 GIF 대신 투명 이미지와 웹 애니메이션 사용을 승인했다. `OverviewArtwork.module.css`의 12초 반복으로 세 그림만 0.08rem 이동·1.012배 확대된다. 실제 설비 가동을 나타내는 애니메이션이 아니다. 헤더 아래 ‘그래픽/图形动效’ 버튼으로 전체 일시정지·재개가 가능하며 `prefers-reduced-motion`에서는 움직이지 않는다. 제목·숫자·차트는 이 애니메이션에 포함되지 않는다.

## 유지한 계약

생산량·계획 배분·진도 계산, API, 백엔드, 스키마, AI 생성 흐름은 변경하지 않았다. AI 표시에는 기존과 동일하게 당일 품질 기준일, ready 상태, qwen38 모델, v1 스키마, 계획·근거 hash, 해당 언어 요약과 비-fallback 결과가 필요하다. 과거 품질 이력은 현재 발생한 불량 또는 원인 확정으로 표시하지 않는다.

## 검증 및 한계

- 단위 검사: 날씨 코드 매핑, 미수신/미확인/지연 구분, AI 표시의 모든 필수 조건, 문장 길이별 회전 시간, 수량 글꼴 단계.
- TypeScript, 변경한 TS/TSX ESLint, production/legacy frontend build.
- 로컬 합성 자료로 한국어·중국어, 긴 문장·8자리 수량, 주야간 날씨, AI 이력 fallback·주의 항목 없음, 초기 조회 실패와 갱신 실패를 확인했다. 회전 버튼·일시정지·언어 전환도 확인했다.
- 출고의 무계획, 미확인 수량, 미수신, 120% 초과 실적을 확인했다. 초과 실적은 120%로 표시하면서 막대만 100% 폭으로 제한하고 접근성 값은 원래 비율을 유지한다.
- 추가 그래픽 검증: 새 정면 크리스털 날씨 6종의 실제 카드 표시, 한국어·중국어 및 8자리 수량, 배경 무늬 제거, 그래픽 버튼 클릭과 Enter 재개 후 3개 이미지의 computed animation state를 확인했다. 모션 감소는 공통 CSS와 버튼 비활성 분기를 검토했다. 마지막 확인 해상도 1943×1257에서는 날짜/위치 및 시각/기온의 top·bottom 차이가 0.02px 미만으로 분수 픽셀 반올림 범위였다. 이미지 3장 로딩 성공과 브라우저 오류 없음도 확인했다.
- 운영 화면에서는 AI 미수신 상태를 관찰했다. 준비된 AI 결과는 합성 fixture 검증이며 운영 AI 수신 확인이나 서버 복구를 의미하지 않는다.
- 확인된 브라우저 레이아웃은 1920×1080 및 기본 창 크기다. 4K viewport 설정은 실제 DOM 해상도에 반영되지 않아 4K 실기 검증 완료로 기록하지 않는다. 실제 현황판의 시청 거리와 4K 기기에서 최종 크기 확인이 필요하다.
- 운영 화면 캡처는 `/tmp`에만 보관한다. 공개 저장소에 운영 수치·품번·상태 화면을 추가하지 않는다.

다음 단계는 로컬 화면을 검토한 뒤 배포하고, 실제 현황판에서 시청 거리와 수신된 AI 문장 길이를 확인하는 것이다.

크리스털 선택 및 정면 글로브 적용은 로컬 구현과 검증을 완료했다. 이전 스튜디오 계열 자산은 사용 참조를 확인한 뒤 제거했다. 시안과 실제 화면의 비교, 원본 경로와 남은 검증 범위는 [design-qa.md](../../design-qa.md)에 기록했다. 운영 배포는 아직 진행하지 않았다.

## 릴리스 검증과 배포 증빙

2026-09-07 사용자 배포 요청에 따라 전체 프런트 검사 157개 통과, 전체 ESLint 오류 0개·기존 경고 31개, production/legacy build 통과를 확인했다. 새 표시 컴포넌트의 독립 읽기 검토와 호출부의 AI 채택·회전·출고 수량 계약 검토에서도 배포를 막는 문제는 발견되지 않았다. 백엔드·DB 마이그레이션·배포 설정 변경은 없다.

위 본문의 미배포 표시는 로컬 UI 검증 당시의 상태다. 최종 릴리스 상태는 `codex/overview-board-polish-20260907` PR 본문의 배포 증빙, 해당 main SHA의 [Test and Deploy](https://github.com/ssoe94/wj_reporting/actions/workflows/test-and-deploy.yml), 운영 [build-info.json](https://wj-reporting.onrender.com/build-info.json)을 함께 확인한다. 운영 수치나 인증 정보가 포함된 화면은 저장소에 추가하지 않는다.
