# 현장 관리자 설치 안내 · 现场管理员安装指南

현장 PC 등록과 운영 적용이 승인된 뒤, 이전 설치본을 보존하고 시범 PC 한 대에서 진행합니다.\
获准登记现场电脑并开展现场试用后，保留原版安装，在一台试点电脑上操作。

## 1. 기존 앱 백업 · 备份旧程序

- 교대 사이에 입력과 인쇄를 마칩니다. 불확실 인쇄는 실물·시리얼을 대조하고 열린 비전 사이클을 종료합니다. 기존 앱과 기존 송신기·스케줄러가 종료된 시점에 EXE와 실행 폴더, 설정·템플릿·드라이버/포트 정보, SQLite DB와 같은 시점의 WAL이 있으면 함께 복사합니다. 비전의 레시피·프로필·확정 기록 경로도 적습니다.
- 在交接班时段完成输入及打印。对不确定打印核对实物和流水号，结束尚未关闭的视觉周期。退出旧程序、旧发送器及其计划任务，再复制 EXE、运行目录、配置、标签模板、驱动和端口信息、SQLite 数据库及同一时点存在的 WAL。记录视觉配方、检测配置及已保存记录的路径。
- 원본 설치와 백업을 별도로 유지합니다. 필요한 경우 가동 중 SQLite는 SQLite 온라인 백업으로 복제합니다. 메인 DB 파일만 따로 복사한 사본을 복구에 사용하지 않습니다. 별도 폴더에서 설정·데이터베이스 무결성·대표 행·인쇄 최종 번호를 확인하고 복사 시각과 해시를 적습니다.
- 分别保留原安装和备份。必须备份运行中的 SQLite 时，使用 SQLite 在线备份。在独立目录检查配置、数据库完整性、代表记录及最后发放编号，并记录时间与校验值。禁止使用运行中只复制了主数据库文件的副本做恢复。

## 2. 중앙 등록과 자격 · 中央登记与凭证

1. 승인된 활성 superuser로 **사출 → 사출 현장 모니터링 → 현장 PC 관리**를 엽니다. PC ID, 표시명, 실제 앱을 등록합니다. 과거 PC의 ID와 원장을 다른 PC에 복제하지 않습니다.
2. **토큰 발급 → 연결 JSON 복사**로 내용을 지정 PC의 제한된 임시 파일에 저장합니다. 발급 화면을 닫으면 평문을 다시 볼 수 없습니다. 운영 연결에는 승인된 HTTPS 주소를 사용합니다. 재발급은 기존 토큰을 회수하므로 장비 교대 시점에 진행합니다.
3. 使用获准且启用的超级管理员账号打开 **注塑 → 注塑现场监控 → 现场电脑管理**。登记电脑 ID、显示名称及实际运行的程序。禁止把旧电脑 ID 和台账复制到另一台电脑并同时发送。
4. 点选 **签发令牌 → 复制连接 JSON**，写入指定电脑上的受限临时文件。关闭签发页面后无法再次查看明文。生产连接使用批准的 HTTPS 地址。重新签发会撤销旧令牌，应在设备交接时更换。

## 3. 포터블 패키지 설치와 설정 · 安装与配置便携包

- 대상 아키텍처와 승인된 패키지 프로필을 맞춥니다. `win7`은 Python 3.8 계열·Chrome 109, `win10`은 Python 3.12 계열·Edge/Chrome 조합을 시범 PC에서 확인합니다. 골격 패키지는 구조 시험에 사용합니다. 설치용 패키지와 승인 경로에서 받은 SHA-256을 대조한 뒤 압축을 풉니다.
- 选择与电脑架构相符的批准包。试点电脑验证 `win7` 的 Python 3.8 系列和 Chrome 109，或 `win10` 的 Python 3.12 系列及 Edge/Chrome。骨架包用于验证目录结构。核对从批准渠道取得的 SHA-256 后再解压。

압축에서 나온 `WJField`에서 설치하고, 전용 작업자 계정으로 설치 경로를 엽니다. 아래는 예시 경로입니다.\
在解压得到的 `WJField` 中执行安装，以专用操作员账号打开安装路径。以下路径仅供示例。

```bat
install.cmd "C:\WJ Field\WJField"
cd /d "C:\WJ Field\WJField"
configure.cmd "C:\Temporary\field-connection.json" --language ko --layout-config "C:\Station Setup\layout.json" --vision-config "C:\Station Setup\vision.json"
start.cmd
```

- 기본 언어는 `--language ko` 또는 `zh`입니다. 에이전트 화면의 변경은 로컬 환경 설정에 저장됩니다. 배치는 일반 작업 PC `agent_only`, 양면 촬영과 나란히 쓰는 PC `split`, V49·UV 전용 PC `companion_full`을 사용합니다. 비전 소스 JSON에서 승인된 기록 경로와 확인된 모드를 지정합니다. V49 상태 조회는 초기 시범에서 꺼둡니다.
- 默认语言用 `--language ko` 或 `zh`。代理界面的选择保存在本机设置。普通作业电脑用 `agent_only`，并排显示双面拍摄时用 `split`，V49 或 UV 专用工位用 `companion_full`。在视觉配置中填写批准的记录路径及确认过的模式。初次试用关闭 V49 状态查询。
- 설치본의 `versions/<버전>/`은 읽기 전용으로 취급합니다. `data/`와 별도 실행 설정 파일은 고정 경로에 두고, 필요한 작업자와 관리자 계정에만 열어 줍니다. 자격 정보는 로그·메신저·시범 기록에 넣지 않습니다. 구성 후 임시 연결 JSON은 안전하게 치웁니다.
- 将 `versions/<版本>/` 作为只读目录。把 `data/` 及单独的运行配置置于固定路径，仅向必要的操作员和管理员授予访问权限。令牌不得进入日志、聊天或验收记录。配置成功后安全清理临时连接 JSON。
- 관리자는 관리자 명령 창에서 `install-autostart.cmd`를 한 번 실행합니다. 운영자와 관리자 계정이 다르면 운영자 창의 `whoami /user`에서 SID를 확인하고 관리자 창에서 `install-autostart.cmd --operator-sid <SID>`로 등록합니다. Windows 작업 스케줄러에서 해당 작업자의 로그온에 시작되는지와 비정상 종료 후 재기동을 확인합니다. 수동으로 정지·업데이트하는 동안에는 새 로그온이 실행되지 않도록 교대 시간을 조정합니다.
- 管理员在提升权限的终端中运行一次 `install-autostart.cmd`。如管理员与操作员账号不同，在操作员窗口运行 `whoami /user` 确认 SID，再在管理员窗口运行 `install-autostart.cmd --operator-sid <SID>`。在 Windows 任务计划程序中确认账号登录后启动及异常退出后重启。停机维护和更新期间安排好交接时间，避免新的登录会话启动程序。

### UV 한·중 패치 · UV 中韩补丁

`versions/<버전>/components/uv/README.md`의 적용·복구 안내에 따라 승인된 원본을 복사하고 복사본에만 적용합니다. 별도 폴더에서 데모로 레이아웃과 한·중 전환·재시작을 먼저 시험합니다. 운영 승인 후 실행기 `work_dir`을 해당 복사본으로 지정합니다. 문제가 있으면 이전 실행 경로를 복원합니다.\
按 `versions/<版本>/components/uv/README.md` 的应用及恢复说明，复制批准的原程序，仅对副本应用补丁。在独立目录先以演示模式检查布局、中韩切换和重启。验收后把启动器的 `work_dir` 指向副本。如有问题，恢复原运行路径。

## 4. Heartbeat 확인과 기존 앱 병행 · 心跳确认及与旧程序并行

1. `start.cmd`나 **WJ Field Agent Portable** 바로가기로 시작합니다. 중앙 현황의 PC ID·최신 heartbeat·등록 앱을 대조합니다. 표준 시험 입력 한 건으로 발생 시각·앱·모드·중앙 검색과 전송 대기 수를 확인합니다. 현장 장치 입력과 실물 판정은 별도로 확인합니다. V49·UV PC에서 백그라운드 현황은 **WJ Field Agent Portable - Status**에서 엽니다.
2. 기존 바코드나 중량 앱이 장치를 계속 사용하도록 하고, 에이전트는 기존 SQLite만 읽도록 `configure.cmd`에 `--legacy-barcode-db <DB>` 또는 `--legacy-weigh-dbs <스캔DB> <인쇄DB>`를 지정합니다. 실행 모드를 바꿀 때는 정지한 뒤 구성을 적용하고 시작합니다. 이미 연결을 구성한 PC는 다음 `configure.cmd` 실행에 연결 JSON을 생략할 수 있습니다. 시범 기록을 원본과 한 건씩 비교합니다. 소스 단절, 누락의 관측 범위, `unknown` 모드를 확인합니다.
3. 运行 `start.cmd` 或 **WJ Field Agent Portable** 快捷方式。在中央页面核对电脑 ID、最新心跳及登记程序。用一笔标准测试数据核对发生时间、程序、模式、中央检索和待发送数量。另行确认现场设备输入和实物判定。V49 或 UV 工位通过 **WJ Field Agent Portable - Status** 打开后台状态。
4. 保持旧条码或称重程序独占设备，代理只读旧 SQLite。在 `configure.cmd` 中设置 `--legacy-barcode-db <数据库>` 或 `--legacy-weigh-dbs <扫码库> <打印库>`。切换运行模式前先停机，再应用配置并重启。已完成连接配置的电脑再次执行 `configure.cmd` 时可省略连接 JSON。逐条比对试点记录，核查数据源中断、可观测范围及 `unknown` 模式。

## 5. 장치 전환과 복귀 · 切换设备及恢复

- 체크리스트 승인 후, 기존 앱·수집기를 정상 종료하고 USB/COM·프린터가 해제됐는지 확인합니다. 새 앱 시작 설정에는 `--barcode-config <규칙 JSON>` 또는 `--weigh-config <규칙 JSON>`을 사용합니다. 처음에는 시험 모드로 승인 샘플을 대조합니다. 바코드·중량 입력을 쓰지 않을 PC의 기존 실행 설정을 비우려면 `--agent-only`를 사용합니다. 비전 설정을 갱신하려면 별도로 `--vision-config`를 지정합니다. 예전 송신기가 새 원장과 같은 장비·이벤트를 이중 전송하지 않도록 확인합니다.
- 清单获批后，正常退出旧程序及采集器，确认 USB/COM 和打印机均已释放。新程序启动配置使用 `--barcode-config <规则 JSON>` 或 `--weigh-config <规则 JSON>`。先在测试模式核对批准样件。无需条码或称重输入的电脑可用 `--agent-only` 清除原输入配置，视觉配置用 `--vision-config` 单独更新。确认旧发送器不会对同一设备和事件重复发送。
- 중량 전환 시 PART별 기존 발급 근거와 마지막 번호를 대조합니다. 기준이 없으면 발급을 보류합니다. 기존 발급이 없다는 검증과 관리자의 확인이 필요한 경우 [시리얼 최초 발급 안내](../../../field_agent/weigh/README.md)를 따릅니다. 기존 앱으로 복귀할 때는 현재 발급을 먼저 중지한 뒤 [담당 이전 절차](issuer-transfer.md)에 따라 신·구 원장과 실물 번호를 대조하고 배정을 정리합니다.
- 切换称重时，按料号核对旧发放记录和最后编号。缺少依据时暂停发号。如需管理员确认从未发放，遵照[首次发号说明](../../../field_agent/weigh/README.md)。恢复旧程序前先停止当前发号，再按[交接流程](issuer-transfer.md)核对新旧台账及实物编号并处理分配。
- 판정·장치 이상으로 복귀하려면 새 입력과 발급을 정지하고, 새 에이전트와 장치 핸들을 닫은 뒤 백업한 기존 설치 경로를 사용합니다. 새 `data/`에는 기록과 대기열을 보존합니다. 장치 복귀와 중앙 데이터 대조는 각각 기록합니다.
- 判定或设备异常需退回时，停止新的输入和发号，退出新代理并释放设备，再使用备份的旧安装。保留新 `data/` 中的记录及队列，分别记录设备退回及中央数据核对结果。

### 라벨 발급 주체 지정과 이전 · 指定及交接标签发号主体

- 중량·라벨 PC는 먼저 **현장 PC 관리 → 발급 품번**에서 중앙 배정을 확인합니다. 하나의 네임스페이스·PART에는 등록 PC와 중량 앱 또는 외부 프로그램 한 곳을 지정합니다. 중앙 배정·중지·해제는 superuser가 사유를 남겨 수행합니다.
- 称重与标签电脑先在 **现场电脑管理 → 发号料号** 核对中央分配。每个命名空间和料号只指定一台登记电脑上的称重程序，或指定一个外部程序。由超级管理员分配、停用及解除，并记录原因。
- 중앙에서 해당 PC용 정책 JSON을 내려받습니다. 에이전트 정지 후 `configure.cmd --issuer-policy "<정책 JSON>"`으로 적용하고 다시 시작합니다. 현황에서 최신 heartbeat의 정책과 중앙 배정이 일치하는지 확인합니다. 배정 없는 PART는 통신이 끊긴 동안에도 예약이 거절됩니다. 현장에 적용하기 전까지 중앙 변경은 에이전트 정책에 반영되지 않습니다.
- 从中央下载该电脑的策略 JSON。停止代理后执行 `configure.cmd --issuer-policy "<策略 JSON>"`，再重启。确认最新心跳中的策略与中央分配一致。未分配料号在断网时也会被拒绝预留。中央变更在现场应用后才反映到代理策略。
- 담당을 변경할 때는 기존 주체 중지 → 최신 heartbeat·전송 확인 및 마지막 예약 번호 대조 → 해제·새 배정 → 새 PC의 이전 상한 확정 순서로 진행합니다. 외부 프로그램은 현장 담당자가 원본에서 중지합니다. [한·중 담당 이전 안내](issuer-transfer.md)
- 更换主体时，依次执行原主体停发、核对最新心跳及发送情况和最后预留号、解除并重新分配、在新电脑确认原上限。外部程序由现场负责人在原程序中停发。[中韩交接指南](issuer-transfer.md)

## 6. 버전 교체와 복원 · 版本更新与恢复

교대 사이에 새 입력을 멈추고 미전송 인쇄·불확실 수량과 진행 중인 비전 사이클을 현장에서 확인합니다. 비전 앱을 정상 종료하고 `stop.cmd`로 에이전트를 정지합니다. 사용 경로에 공백이 있으면 큰따옴표를 사용합니다.\
在交接班时停止新输入，现场核查等待发送的打印、未确认数量和仍在运行的视觉周期。正常退出视觉程序，再执行 `stop.cmd` 停止代理。路径含空格时加双引号。

```bat
update.cmd "C:\Approved Packages\WJField-next.zip" --confirm-idle
start.cmd
```

- ZIP 옆의 승인된 `.zip.sha256`과 패키지 내부 무결성 검사, 새 런타임 자가 점검이 성공한 뒤에만 `current.txt`가 바뀝니다. 진행 중 작업이 확인되면 원인을 처리하고 다시 실행합니다. 전환 뒤 화면 버전, 업무 모드, 중앙 수신·장치, 이전 원장을 확인합니다.
- ZIP 旁须有已批准的 `.zip.sha256`。归档及内部文件检查、候选运行时自检通过后才切换 `current.txt`。如检测到未结束的工作，先处理再重试。切换后核对界面版本、作业模式、中央接收、设备和原台账。
- 복귀는 동일한 정지 절차 뒤 `rollback.cmd --confirm-idle` 또는 `rollback.cmd <버전> --confirm-idle`과 `start.cmd`를 사용합니다. 원장 호환성 확인이 필요합니다. 이전 날짜의 DB를 원래 경로에 덮어쓰지 않습니다. 손상 복구는 원장 세대와 중앙 seq를 대조한 뒤 [백업·복원 안내](../../../field_agent/README.md#백업과-복원)를 따릅니다.
- 回滚前按同一流程停机，再执行 `rollback.cmd --confirm-idle` 或 `rollback.cmd <版本> --confirm-idle`，最后执行 `start.cmd`。须通过台账兼容性检查。禁止用旧数据库覆盖现有路径。台账损坏时先核对台账世代与中央 seq，再按[备份和恢复说明](../../../field_agent/README.md#백업과-복원)处理。
- 시범 종료 시 `uninstall.cmd --confirm-idle`로 바로가기·자동 시작·버전 파일을 제거하고 `data/`는 보존합니다. 자동 시작 제거 권한이 운영자에게 없으면 관리자가 `remove-autostart.cmd`를 실행한 뒤 운영자 계정에서 제거합니다. 관리자가 더 이상 송신할 필요가 없다고 확인하면 중앙 PC 사용 상태와 장비 토큰을 정리합니다.
- 结束试用时执行 `uninstall.cmd --confirm-idle` 移除快捷方式、自启任务和版本文件，保留 `data/`。操作员无权移除自启任务时，由管理员执行 `remove-autostart.cmd`，然后在操作员账号下完成卸载。主管确认无需再发送后，处理中央电脑的启用状态和设备令牌。
