# 라벨 발급 담당 이전 · 标签发号交接

제품 규칙의 사이트 코드와 업체 코드를 합친 네임스페이스와 PART의 조합에는 발급 PC·프로그램 한 곳만 배정합니다. 중앙 등록부에서 상태를 관리하고, 현장 담당자가 해당 PC에 설정을 적용합니다. 발급 프로그램이 두 곳에서 같은 라벨을 만들지 않도록 아래 순서대로 진행합니다.\
由产品规则中的站点代码与供应商代码组成命名空间，每个命名空间和料号组合只分配一台发号电脑及一个程序。在中央登记簿管理状态，由现场人员将配置应用到相应电脑。按以下顺序交接，避免两处程序生成同一标签。

| 순서 · 步骤 | 한국어 | 简体中文 |
| --- | --- | --- |
| 1. 기존 발급을 마무리합니다 · 收尾旧发号 | 기존 담당자는 해당 PART의 새 계량·예약을 중지합니다. 대기 인쇄·박리를 마무리하고, 불확실 인쇄는 실물과 원장을 대조합니다. 취소했거나 출력 여부를 확인하지 못한 번호도 이미 예약됐다면 마지막 번호 대조에 포함합니다. | 原负责人停止该料号的新称重及预留，处理待打印及揭标，打印结果不确定时核对实物和台账。已预留的号码即使取消或未确认出纸，也计入末号核对。 |
| 2. 권한을 회수합니다 · 撤回权限 | 중앙 관리자는 **사출 현장 모니터링 → 현장 PC 관리 → 발급 품번**에서 기존 배정에서 **발급 중지**를 선택하고 사유를 남깁니다. **발급 설정 다운로드**에서 기존 PC용 새 정책을 받습니다. 현장 담당자는 에이전트를 정상 정지하고 새 정책을 적용한 뒤 재시작합니다. | 中央管理员在 **注塑现场监控 → 现场电脑管理 → 发号料号** 对原分配选择**停止发号**并记录原因，通过**下载发号设置**取得原电脑的新策略。现场人员正常停止代理、应用新策略后重启。 |
| 3. 중지와 마지막 번호를 확인합니다 · 确认停发与末号 | 중앙 관리자는 **최근 3분 이내 heartbeat**, 받은 정책 적용 이벤트와 미전송 0건을 확인합니다. 아직 정책에 해당 PART가 있거나 중앙과 정책 해시·리비전이 다르면 해제가 보류됩니다. 기존 원장과 중앙의 예약 기록을 대조해 PART별 각 인쇄 날짜의 마지막 예약 번호를 확인합니다. 확인이 끝날 때까지 발급 담당을 넘기지 않습니다. | 中央管理员确认**过去 3 分钟内的心跳**、已收到的策略应用事件及待发送为 0。若策略仍包含该料号，或哈希值、版本与中央不一致，则暂缓解除。对照原台账和中央预留记录，核对各料号、各打印日期的最后预留号。确认完成后方可交接。 |
| 4. 해제 후 새 주체를 배정합니다 · 解除后分配新主体 | 중앙 관리자는 해제 당일과 이전에 인계받은 날짜의 상한을 빠짐없이 확인해 사유와 함께 남겨 **배정 해제**를 완료한 뒤 새 PC·프로그램을 배정합니다. 같은 네임스페이스·PART에 대해 이전 주체의 배정이 해제된 것을 확인합니다. 새 PC용 정책을 내려받습니다. | 中央管理员完整核对解除当日及之前已交接日期的上限，录入上限及原因，完成**解除分配**后再分配给新电脑及程序。核对同一命名空间和料号的原分配已解除，随后下载新电脑的策略。 |
| 5. 새 PC에서 상한을 확정합니다 · 在新电脑确认上限 | 새 PC에서 에이전트를 정상 정지하고 새 정책을 적용합니다. 관리자가 **이전 주체 상한**을 발급 바닥값으로 확정한 뒤 재시작합니다. 첫 예약이 해당 날짜의 기존 예약 상한을 초과했는지와 중앙에 새 주체가 표시되는지 확인합니다. | 在新电脑正常停止代理并应用新策略。由管理员把**原主体上限**确认为起始下限后重启。核对首笔预留高于对应打印日期的原上限，并确认中央显示新主体。 |

해제가 계속 보류되면 정책 적용 이벤트가 중앙에 수신됐는지 확인합니다. 전송 대기를 0건으로 비우고 전송 오류를 해소합니다. PC 시계를 5분 이내로 맞추고 같은 PC ID로 송신 중인 인스턴스를 한 곳으로 정리한 뒤 새 heartbeat를 확인합니다.\
解除仍被暂缓时，确认中央已收到策略应用事件。将待发送清为 0 并处理发送错误，把电脑时钟偏差调整到 5 分钟以内。让同一电脑 ID 仅保留一个发送实例，然后确认新的心跳。

## 현장 명령 · 现场命令

기존 PC와 새 PC에는 각각 해당 PC에서 내려받은 최신 설정 파일을 적용합니다. 다음은 설치 폴더에서 실행하는 예시입니다.\
在原电脑和新电脑分别应用为该电脑下载的最新配置。以下命令在安装目录执行。

```bat
stop.cmd
configure.cmd --issuer-policy "C:\Station Setup\issuer-policy.json"
start.cmd
```

새 PC는 정책을 적용한 뒤 재시작 전에 관리자 창에서 이전 상한을 확정합니다. 아래 경로·품번·사유는 예시입니다.\
新电脑应用策略后，在重启前通过管理员命令窗口确认原上限。下列路径、料号和原因仅供示例。

```bat
"versions\<활성버전>\python\python.exe" -m field_agent confirm-serial-transfer --data-dir "data" --weigh-config "C:\Station Setup\weigh-rules.json" --part-no "SYNTH-PART" --reason "원장 대조 완료 / 台账核对完成"
```

담당 이전 상한은 상하이 현지 **인쇄 날짜**로 확인합니다. 중앙 검색의 업무일은 08:00에 바뀌므로 날짜 경계에 해당하는 두 업무일의 예약을 함께 확인합니다. 4자리 base34 번호는 정수로 대조한 뒤 입력합니다. 예를 들어 `0010`은 34입니다. 0은 해당 날짜의 예약이 없음을 원장으로 확인했을 때만 입력합니다.\
按上海本地**打印日期**核对交接上限。中央查询的业务日在 08:00 切换，须同时检查日期边界涉及的两个业务日。四位 base34 流水号按整数核对并录入，例如 `0010` 等于 34。只有台账确认该日期无任何预留时才录入 0。

이전 당일에는 중앙의 상한을 확정합니다. 날짜가 넘어갔다면 이전 날짜의 상한을 보존하고, 새 인쇄 날짜에 해당하는 상한이 없을 때는 최초 발급 근거를 확인합니다. [최초 발급 근거 안내](../../../field_agent/weigh/README.md)\
交接当日须确认中央登记的上限。跨日后保留已交接日期的上限，新打印日期没有对应上限时，确认该日首次发号依据。[首次发号依据](../../../field_agent/weigh/README.md)

## 외부 프로그램과 복귀 · 外部程序与恢复

- TV Stand·NLP 등 외부 프로그램은 프로그램 이름과 PC 메모로 중앙에 등록합니다. 기존 발급 담당이 외부 프로그램이면 해당 프로그램에서 담당자가 발급을 중지하고 그 원장에서 상한을 확인합니다. 에이전트가 제어하는 차단 범위는 자체 발급입니다.
- 在中央登记 TV Stand、NLP 等外部程序时填写程序名称及电脑备注。原发号主体是外部程序时，由现场负责人在该程序内停发并从原台账核对上限。代理可控制其自身的发号。
- PC를 복귀하거나 오래된 백업·실행본을 사용해야 하면 먼저 해당 PART의 발급을 정지합니다. 동일한 활성 데이터 원장에 저장된 회수 정책은 이전 정책 파일을 다시 적용해도 되살아나지 않습니다. 별도 데이터 폴더, 백업 복원, 외부 EXE를 사용할 때는 중앙 배정과 최신 정책을 다시 대조합니다. 다른 PC로 발급을 넘겼다면 같은 이전 절차로 다시 배정합니다.
- 恢复电脑或使用旧备份、旧版本前，先停止该料号发号。在同一启用台账中应用撤回后，重新应用旧策略文件也无法恢复原权限。使用其他数据目录、恢复备份或使用外部 EXE 时，重新核对中央分配和最新策略。若发号职责已交给另一台电脑，按同一交接流程重新分配。
- 서로 다른 PC에서 같은 바코드가 정상 처리됐다는 예외는 실물과 작업 경로를 조사할 단서입니다. 라벨, PC·프로그램, 서로 다른 스캔 시각과 해당 날짜의 예약 원장을 확인합니다.
- 不同电脑正常处理同一条码的异常是调查实物与作业路径的线索。核查标签、电脑及程序、各次扫描时间和相关打印日期的预留台账。
